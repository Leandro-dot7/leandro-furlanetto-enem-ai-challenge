# Argos — auditoria do RAG inicial do Tutor

**Data:** 19/09/2026  
**Escopo autorizado:** alterações locais do backend e ingestão da API pública `api.enem.dev`; auditoria estática e validações locais. Não houve teste contra dados de estudantes nem exploração destrutiva.  
**Snapshot anterior:** commit `401a9bc` (`chore(snapshot): save SaaS state before RAG`).  
**Corpus usado:** piloto de 2023, 180 questões, cache local ignorado pelo Git.

## Resumo executivo

Não foram encontrados segredos expostos, rota pública nova para o corpus, bypass de autenticação ou vulnerabilidade crítica introduzida pelo RAG. A ingestão respeita o limite documentado da API, grava o corpus localmente e o Tutor recupera no máximo uma referência curta por padrão.

Existe um risco arquitetural residual: o corpus externo é conteúdo não confiável e pode conter prompt injection ou erro de gabarito. A mitigação atual instrui o Gemini a tratar referências como dados, remove os delimitadores de prompt antes do envio e mantém o índice fora do caminho de requisição externa. A validação adversarial do comportamento do modelo continua pendente.

## Achados

### [ARG-RAG-001] [Severidade: Informativa] — Fonte externa não é oficial do INEP

- **Categoria:** Supply chain / integridade de dados.
- **Componente afetado:** `backend/scripts/ingestEnemRag.js`.
- **Descrição:** a API é comunitária; a aplicação registra `source`, `sourceBaseUrl`, ano e data da coleta no cache, mas não transforma a API em autoridade oficial.
- **Evidência:** o cache piloto registra `source: api.enem.dev` e `sourceBaseUrl: https://api.enem.dev/v1`; o serviço não aceita URLs vindas do usuário.
- **Impacto:** uma alteração upstream pode introduzir texto ou gabarito incorreto no contexto do Tutor.
- **Mitigação atual:** corpus local, revisão por piloto e recomendação de conferência com INEP.
- **Próximo passo:** adicionar checksum/manifesto aprovado e validação cruzada com fonte oficial antes de publicar questões.

### [ARG-RAG-002] [Severidade: Média — risco arquitetural] — Prompt injection no conteúdo recuperado

- **Categoria:** OWASP LLM — prompt injection indireta / data poisoning.
- **Componente afetado:** `backend/services/enemRagService.js` e `backend/services/geminiService.js`.
- **Descrição:** `context` e alternativas da API entram no prompt do Tutor. O conteúdo pode conter instruções textuais, mesmo que não seja uma instrução confiável.
- **Evidência:** o Tutor encapsula o conteúdo em `<REFERENCIAS_RECUPERADAS>`, limita-o a 3.000 caracteres, remove os delimitadores repetidos e a system instruction ordena ignorar instruções recuperadas.
- **Impacto:** se a fonte for adulterada, o modelo pode seguir parte do texto recuperado, responder fora do escopo ou produzir orientação errada.
- **Estado:** mitigação parcial; não confirmado dinamicamente contra um corpus malicioso.
- **Recomendação:** adicionar corpus de canários adversariais, avaliação automática de obediência e aprovação/checksum dos arquivos antes da ingestão.

### [ARG-RAG-003] [Severidade: Baixa] — Dependência de rate limit externo durante ingestão

- **Categoria:** Disponibilidade / abuso de recurso.
- **Componente afetado:** `backend/scripts/ingestEnemRag.js`.
- **Descrição:** a API documenta limite de 1 requisição por segundo sem cache.
- **Evidência:** o job espera 1.100 ms entre chamadas, usa páginas de 10 itens, timeout de 20 s e grava por arquivo temporário + rename.
- **Impacto:** uma ingestão interrompida não deve corromper o arquivo anterior, mas pode terminar incompleta.
- **Mitigação atual:** fila sequencial, timeout e escrita atômica.
- **Recomendação:** adicionar lock de execução, retry com backoff e manifesto que marque o ano como completo somente após todas as páginas.

### [ARG-RAG-004] [Severidade: Informativa] — Cache local não é exposto ao cliente

- **Categoria:** Exposição de dados / autorização.
- **Componente afetado:** `backend/data/enem-rag` e `backend/services/enemRagService.js`.
- **Descrição:** não há rota Express para listar ou baixar o corpus; a rota do Tutor continua protegida por `requireSupabaseUser` e `aiRateLimit`.
- **Evidência:** o cache `backend/data/enem-rag/*.json` está no `.gitignore`; a busca ocorre somente no backend e retorna apenas contexto para o Gemini.
- **Resultado:** nenhum bypass de autenticação ou exposição direta foi identificado nesta rodada.

## Verificações executadas

- `node --check` nos serviços, controlador e script de ingestão: aprovado.
- Ingestão real de 2023: 180 questões salvas; nenhuma chamada é feita durante a pergunta após o cache ser carregado.
- Busca local de teste sobre “dislexia e interpretação”: retornou referência curta com fonte e gabarito.
- `npm run lint` (frontend): aprovado; somente avisos preexistentes.
- `npm audit --omit=dev --audit-level=high` (backend): 0 vulnerabilidades.
- `npm audit --omit=dev --audit-level=high` (frontend): 0 vulnerabilidades.
- `git diff --check`: aprovado, com avisos conhecidos de LF/CRLF.
- Busca por `dangerouslySetInnerHTML`, `SUPABASE_SERVICE_ROLE` e marcadores de HTML executável no corpus: nenhum resultado no corpus; o renderer do Tutor não usa HTML bruto.

## Limitações

- Não foram usados Playwright, conta autenticada ou chamada real ao Gemini nesta auditoria.
- A análise não prova que o modelo recusará todos os canários de prompt injection; requer teste de comportamento com um corpus controlado.
- O RAG inicial é lexical, não vetorial. Ele reduz chamadas externas e mantém contexto curto, mas a relevância deve ser medida antes de migrar para embeddings/pgvector.

## Conclusão

O RAG inicial pode seguir para homologação controlada. Não há bloqueio crítico aberto. Antes de disponibilizar o corpus ampliado ao público, executar validação cruzada com o INEP, adicionar checksum/lock/retry no job e rodar uma suíte adversarial de prompt injection sobre o conteúdo recuperado.
